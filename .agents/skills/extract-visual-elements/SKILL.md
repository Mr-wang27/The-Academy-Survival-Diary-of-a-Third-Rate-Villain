# 人物与场景元素提取

根据用户提供的图片、图片组或素材文件夹，拆解可复用的视觉资源，并在项目 `output` 下建立完整档案。用于后续漫画、漫剧和视频生成的一致性管理；不改动原始参考文件。

## 对象识别与范围

用户未说明类型时，先观察视觉主体与画面用途，自行判定：

- **人物**：以角色为核心，整理外形辨识点、发型、服装、鞋袜、佩饰、随身物、姿态特征，以及可复用的面部表情特写。
- **场景**：以环境为核心，整理空间结构、建筑、家具、植物、自然物、光线、氛围和可交互道具。

同一画面同时含有人物与场景时，优先处理视觉中心；若用户明确指定对象则遵从其范围。未展开的次要对象在档案中说明即可。

## 提取原则

1. 先盘点所有参考图，以重复出现或可由多视角互证的信息锁定设计；不将景别、偶发阴影或绘制瑕疵当作独立元素。
2. 按后续生成可单独调用的粒度拆解。人物按身体特征、发型、服装层、鞋履、配饰、随身物与**面部表情特写**划分；场景按空间、建筑、陈设、植被、自然物、光源与道具划分。表情特写按可见情绪命名，如“开心”“愤怒”“悲伤”“惊讶”“平静”等，并记录眉眼、嘴形、脸颊与头部角度等辨识点。
3. 遮挡、裁切或局部可见的元素，基于可见材质、轮廓、连接位置和整体设计作**保守补全**。所有无法直接证实的内容标为“推定”；不虚构醒目图案、文字、品牌、复杂结构或剧情信息。
4. **每一个已列入清单的元素都必须制作一张独立、确定的图片**，保存为 PNG。不可只写文字、只引用原图，或仅制作“关键元素”。图片须只呈现该元素：服装、配饰、道具、植物、家具等以干净中性背景或透明背景单独展示；人物脸部／表情以清晰特写展示；空间结构、建筑或大型环境元素可保留必要的局部关系，但不得混入无关对象。保持原始设计语言、比例、材质与配色；补全区域只可采用已标注的保守推定。

## 漫画表情与心理状态提取（人物必做）

对人物参考中的**每一张含有可辨识面部**的分镜逐一盘点，不能只从设定图或全身图挑选表情。表情命名和资源生成应按以下顺序完成：

1. 记录源文件、角色是否可辨识、脸部景别与可见的眉、眼、嘴、脸颊、头部角度和动作；同一表情的重复镜头合并为一项。
2. 读取角色对应的对白、旁白、拟声词及紧邻分镜的可见语境；区分角色自己的话、他人的话与叙述文字。只将能由画面和配文共同支持的心理状态写入档案。
3. 用“主情绪＋修饰状态”命名资源，例如“开心_害羞”“小窃喜_略害羞”“惊讶_警觉”。若文本与脸部表现不完全一致，优先保留可见表情，并将心理解释标为“推定”。
4. 为每个不同的可复用表情制作一张正面或最可辨识角度的清晰脸部特写 PNG。生成提示必须锁定角色的脸型、发色、瞳色、瞳孔／眼线特征、常服领口和已有发饰；只改变眉眼、嘴形、脸颊红晕、视线与头部角度。不要把对白框、文字、其他角色、手势或场景带入表情资源。
5. 在档案的“面部表情资源”中逐项写明：来源文件、画面／配文证据、推断的心理状态、可见面部特征、状态（明确／推定）与 PNG 路径。配文无法可靠辨认时，说明“仅据画面判断”，不虚构剧情。
6. 完成前逐项核对：每一项已记录表情都有对应 PNG；每个 PNG 在档案有来源与心理说明；同一类别不得只有“平静”而漏掉参考中明显不同的开心、害羞、惊讶等表情。

## 归档结构

每个角色或独立场景使用一个目录，名称优先采用用户提供的名称；未命名时使用简短、稳定的中文名：

```text
<对象档案目录>/
├── 元素档案.md
└── 元素/
    ├── 01_<元素名称>.png
    ├── 02_表情_开心.png
    └── ...
```

不混放多个角色或多个独立场景。所有条目均须在 `元素/` 中有一张同编号、同名称的 PNG；`元素档案.md` 中的每项都必须引用其相对路径。参考原图可保留在用户原始位置，无需复制到档案目录。`元素档案.md` 使用简洁、客观、可检索的视觉描述，并包含：

- 类型、名称、参考图范围及一句话整体定位。
- 元素清单：编号、名称、分类、可见特征（颜色／材质／形状／位置）、状态（明确／推定）及对应的 `元素/<编号>_<名称>.png` 文件。
- 人物档案：脸型、发型、五官辨识点、体型比例、服装层次和配戴关系；另列“面部表情资源”，记录表情名称、可见情绪特征、关键眉眼嘴形、头部角度、状态及对应特写资源文件。
- 场景档案：空间层级与方位、主色调、时间／天气、主光源方向、前中后景关系和氛围。
- 一致性提示：后续生成必须保留的关键设计锚点，以及仍待确认的推定项。

完成后报告输出目录、识别类型及推定元素数量。
