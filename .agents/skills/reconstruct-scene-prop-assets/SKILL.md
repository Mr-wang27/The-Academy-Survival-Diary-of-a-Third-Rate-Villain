# 场景与道具资源重建

将零散参考整理为可复用的场景或道具设定。已有设计由原始证据决定；看不到但交付所必需的部分，按现有形体和风格作最小补全，逐项标为推定。不要把新生成图中的细节回写为原作事实。

## 适用范围与工具

- 场景：房间、建筑、街道、庭院、自然环境等。重点锁定平面关系、入口和可行走区域、前中后景、固定陈设、材质、色彩、光源与镜头方位。
- 道具：家具、武器、器皿、徽章、载具等可独立复用的物件。重点锁定轮廓、部件连接、相对尺寸、材料、装饰位置与不同视角的结构一致性。
- 用户仅要求创建或修改 Skill、分析参考、列档案或审核时，不生成图片。用户要求制作资源时，完成所请求的绘图与验收。
- 实际绘图前读取项目相邻的 `../imagegen/SKILL.md`；若不可用，查找当前可用的 imagegen Skill。用图像查看工具逐张检查本地参考，并按图像工具实际接口传入图片；提示词中的路径不能代替真实参考图。
- `extract-visual-elements` 负责拆解元素清单；本 Skill 负责将指定场景或道具变成稳定的可复用设定图。人物三视图使用 `reconstruct-character-assets`，相邻分镜中的单幅人物拼接使用 `comic-panel-character-reconstruction`。

## 1. 明确对象、参考和交付

确认是一个场景、一个道具，还是多个独立对象。不同空间或不同型号分目录处理；同一场景的昼夜、损坏前后等版本也分开标记，不能混成一张“标准设计”。按用户指定的参考、视角、比例、画风、背景和保存位置执行；未指定时，优先制作证据最充分的基准视图，再制作完成请求所需的补充视图，不自行扩大数量。

只给文件夹时枚举图像，区分原始分镜、用户确认设定、拼接或增强图、既有生成图。新生成图仅用于跨图一致性，不自动成为独立来源。记录无法读取的文件及其对交付的影响。

## 2. 建立证据档案

读取并填写 [证据档案模板](references/asset-record.md)。逐张查看参考的有用细节，给原始证据编号 R01、R02 等，注明来源、画面位置、可见区域、景别及局限。区分“已确认”“用户指定”“有冲突”“不可见”“推定补全”；给补全编号 C01、C02 等，关联其依据和适用视角。

按局部可见证据决定优先级：用户明确指定的设定用于其指定范围；对应部位清楚的原始参考优先；多张原图交叉核对；派生图仅作辅助。区分透视造成的形变与物件本体形状、投影与固有颜色、临时摆放与固定布局、镜像画面与真实左右。方位始终用同一个坐标约定，例如“面对正门时左侧”，记录在档案中。

场景须画出简单的空间关系图或文字方位表：边界、出入口、楼梯、窗、通道、固定大型物、人物活动区与相邻空间。道具须写明部件表、连接关系、可动处、正反面及装饰朝向。参考未给出绝对尺寸时只写相对比例，不编造数字尺寸。详见 [场景与道具检查项](references/visual-review.md)。

## 3. 处理冲突与缺失

先判断差异是否来自时间、光照、拍摄方向、透视、损坏状态或不同版本。无法解释且会改变关键结构的可见冲突，记录候选方案并向用户提出具体选择；先完成不受影响部分。若只是未展示的背面、转角或底部，默认依据现有轮廓、材料与设计语言作最少必要补全，不因此停止全部绘图。

补全不得新增显眼纹章、文字、标识、剧情物件、门窗、机关或复杂装饰。场景不得凭空改变门窗位置、通道连通性或固定陈设；道具不得改变已见部件数量、连接方式或开合逻辑。若用户明确要求“未知部分不要推定”，只交付有证据支持的范围并列出缺口；不要用裁切或遮挡掩盖已请求且可完成的视图。

## 4. 生成设定图

将档案中的具体事实写进提示词，并明确每张参考负责的区域和优先级。先制作证据最充分的基准图；检查后，后续视图同时参考原始证据和通过检查的基准图。保留原漫画线条、色块、材质表达与画面气氛；设定图可使用中性背景，但用户要求原场景氛围时保留该氛围。

场景生成时固定空间坐标与观察方向，说明相机位置、透视类型、视线高度、入口和固定物的相对位置。不同镜头可以改变视角与光线，不能改变平面布局。俯视图或平面示意若用户未要求，不必额外生成；若生成，应与透视图的入口、窗和大型物一致。

道具生成时统一对象轴线和相对比例。按用户请求制作正、侧、背、俯视或三分之四视图；在视图中保留同一部件的形状、数量和左右位置，避免镜像代替反面。透明或白色背景适合独立道具，若材质需要环境光帮助辨识，可补充一张使用情境图，但不以情境图代替请求的设定视图。

默认分别生成视图，便于逐张检查；用户只要合版时可直接制作合版并逐视角验收。保存新版本，不覆盖参考或已交付版本。记录实际生成工具、所传参考、完整提示词和输出文件。

## 5. 视觉验收与交付

实际打开每张输出，按 [视觉验收清单](references/visual-review.md) 对照原图、档案与其他视图。局部失真只针对该处修正，并复查其他锁定细节是否漂移。将结果标为“待检查”“需修正”“已检查符合可见参考”或“已检查且含推定补全”。补全通过一致性检查后可交付，但不能称为原作确认。

优先保存到用户指定目录；否则使用 `output/scene-prop-assets/<场景或道具名称>/<版本>/`。每个对象保存 `asset-record.md`、`generation-log.md`、`review.md` 和实际生成的图片。档案与日志使用 [证据档案模板](references/asset-record.md) 的字段，图片文件名标出视角与版本，如 `front-v001.png`、`back-v001.png`、`overview-v001.png`。最终给出文件链接、参考依据、推定项与未解决问题；只称已实际生成且检查过的资源为完成。
