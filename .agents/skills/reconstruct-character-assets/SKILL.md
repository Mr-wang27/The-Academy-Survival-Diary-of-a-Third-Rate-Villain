# 漫画角色三视图与头像还原

将参考证据、保守补全、生成约束和视觉验收连成一个流程。已有证据的设计严格保留，缺失部分默认依据现有设计适当补全，完成用户请求的全部资产。分别验收原图还原与补全一致性；不把推定标为原作事实，不承诺百分之百一致。

## 工具与范围

- 负责参考整理、细节约束、生成顺序和验收；实际绘图遵循 ImageGen。
- 首次绘图前读取项目相邻的 `../imagegen/SKILL.md`；不可用时查找当前会话提供的 imagegen Skill。遵循当前实际工具接口，不照搬过时参数。
- 默认调用内置图像生成工具。不要自行切换到 API、CLI 或外部服务；按 ImageGen 的回退规则处理工具不可用情况。
- 先用图像查看工具查看本地参考，再按工具支持的方式真实传入图片。提示词中的文件路径不能代替传图。只传已检查且与本次视角相关的参考，说明每张职责。
- 用户只要求分析、创建 Skill 或审核时，不自动生成图片。用户要求制作资源时，执行已授权的分析、绘图和验收，不重复询问是否开始。
- 将角色和服装档案保存在项目输出目录，不把某个角色的特征写入通用 Skill。

## 1. 确定素材与输出范围

识别角色、服装版本、用户指定参考范围、输出视角及保存位置。只生成请求的资产。

默认采用“忠实还原＋保守补全”模式；调用本 Skill 即可按此流程处理参考不足，无需逐项请求补全许可。“严格遵循原作”表示严格保留已有设计，不单独等同于禁止补全。若用户当前明确要求“未知细节不要补全”“只画有证据的部分”，则采用“证据限定”模式。用户最新明确选择优先；用户只修改 Skill 时不要顺带重新生成既有角色图片。

无额外要求时，将三视图理解为正面、严格侧面、背面全身。选择参考更充分的一侧，注明角色自身左或右侧。将“证件照”理解为原漫画画风的正面头肩像，不转为真人照片，不套用真实证件规范。默认使用中性表情、平视、纯白背景、自然站姿和原有身体比例；用户指定要求优先。

只给文件夹时枚举图像并区分原始参考与既有输出；给出文件清单时以清单为输入范围。不要把生成输出子目录自动作为新证据。记录无法读取的文件，继续检查可读素材。

## 2. 建立角色证据档案

读取 [角色档案模板](references/character-record.md)，在输出目录建立 `character-record.md`。逐张查看本次采用的参考，分配 R01、R02 等编号，记录路径、来源、可见部位和限制。查看长图中的局部细节，不能仅凭缩略图判断饰件或瞳孔。

按每个部位选择证据，而非让一张图决定所有细节：

1. 遵循用户明确指定的权威设定，记录适用范围。
2. 优先使用来源确认、细节清楚的原始漫画，结合多图交叉检查。
3. 将拼接、重绘、增强、生成还原图作为辅助，核实具体细节能否追溯到原图。仅凭“完整”“高清”“还原”等文件名不能确认来源。
4. 将新生成图视为派生资产；只有经过检查的部分可用于保持一致性，不得将新增细节循环当作原作证据。

逐项记录脸型、五官、眼型瞳色、眉睫、发际线、刘海分束、发长发色、肩腰比例、体型肤色、领口、前后衣片、袖口、裙摆开衩、饰品形状与数量、佩戴侧、腿部露肤、袜口、鞋口、鞋尖和鞋跟。保持线条和上色方式，不自动美化、添加纹样或拉长腿。

区分光影与固有颜色、透视与真实比例、动作褶皱与衣服结构。左右统一按角色自身定义，必要时另记画面位置。不得镜像角色来生成另一侧。

将每项标记为“已确认”“有冲突”“不可见”“用户指定”或“推定补全”，关联参考编号。为每项补全分配 C01、C02 等编号，记录所依据的 R 编号、设计理由、适用视角和版本。不要编造精确测量或数值置信度。

## 3. 处理冲突与未知

先根据来源、局部清晰度和多图证据解决可解释差异，并记录理由。不要将互相矛盾的可见设计当作缺失资料，也不要将不同服装混合。对会改变可见设计且无法解决的冲突，提出具体选择问题；继续不受影响的工作，已有选择不重问。

逐部位核对证据，不因缺少某个完整视角就判定整个视角不可制作。发现会影响输出的缺失后，默认读取并执行 [参考不足时的补全流程](references/missing-reference-completion.md)：先建立缺失清单与角色氛围约束，再确定最少必要设计、写入档案，最后生成缺失视角并检查跨图一致性。不得仅因缺少背面、鞋后跟或局部衣片参考而跳过请求的输出。

证据限定模式下，不生成必须推定的可见部位；完成有依据的部分并说明缺口。若未知部分会被原有头发或衣物自然遮挡，保留遮挡，无需设计其内部。两种模式均不得用新增遮挡、裁切或改姿势隐藏验收失败。

## 4. 组织生成

读取 [生成提示词模板](references/generation-prompts.md)，填入档案中的具体特征，删除不适用字段，禁止提交占位符。

优先制作并检查证据最充分的视角作为基准（通常为正面）；再结合原始参考与已登记补全方案生成其他视角和头像，最终完成全部请求。正面资料不足时先以证据充分的侧面或其他视角建立基准，再补全正面。仅请求头像时直接建立脸部基准，不额外生成全身。每次保留原图约束，禁止只参考上一张生成图不断衍生。

统一三视图的身高、头身比、肩线、腰线、膝线及脚底高度。采用平视、低透视设定图构图，完整显示头发和鞋子，姿势不遮挡需要展示的服装。不得把俯视图的腿部缩短当作真实比例。

默认分别生成各视角，便于检查与修正。需要合版时，在单视图通过后制作；用户只要一张合版时可直接生成合版，并逐个视角验收。未核验的视角不能标为完成。

头像沿用同一脸型、眼型、发际线、刘海和领口。用户授权裁切且正面资源分辨率足够时，可复用已通过检查的正面；否则通过 ImageGen 生成或编辑，并重新验收。图像编辑默认使用 ImageGen，除非用户明确授权其他方式。

不要虚构工具参数、输入数量、输出尺寸能力或保存路径。根据工具实际返回文件将成果复制到项目，避免覆盖原始参考和已有版本。

## 5. 验收与定向修正

读取 [视觉验收清单](references/visual-review.md)，实际打开每张输出并对照对应原图。将输入参考、完整生成提示、版本、检查结果及未解决项保存为 `generation-log.md` 与 `review.md`。

针对具体失败修改对应部位，并重复其他锁定项；修改后检查该部位及其他特征是否漂移。不要把整张重新设计当作局部修正。反复失真或工具失败时报告具体障碍及可交付部分，不无限重试、不声称全部通过。

将资产状态区分为“待检查”“需修正”“已检查符合可见参考”“已检查且含推定补全”。对已确认部分检查原图还原，对补全部分检查登记方案、结构、氛围和跨图一致性；两类检查均通过后，含补全的资产可以作为完整交付。不得声称补全部分经原作证实。自动视觉检查不能替代用户最终美术判断。

## 6. 保存与交付

优先使用用户指定位置；否则使用当前项目的 `output/character-assets/<角色>/<服装>/`。选择下一个未占用版本号，记录实际尺寸和背景。

按请求保存 `front-v001.png`、`left-profile-v001.png` 或 `right-profile-v001.png`、`back-v001.png`、`portrait-v001.png`、可选 `turnaround-v001.png`，以及角色档案、生成记录和验收记录。只交付实际生成内容。

最终提供图片和可点击文件链接，说明实际工具路径，并指出冲突、推定或待修正项。不要声称无依据的完整性或百分之百一致。
